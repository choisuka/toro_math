# 시험대비 패턴 서랍 — 명제

`toro-examprep-generator`가 문제 세트를 설계할 때 참고하는 유형 목록입니다. 각 서랍은
①메커니즘 ②연결되는 기존 개념카드(있으면 — 역참조 필수 대상) ③난이도 신호(체이닝 단계 /
케이스분류 개수 / 정수론적 요소 / 동시조건 개수)로 정리했습니다.

**범위**: 2022 개정 공통수학2 "명제" 소단원(`공수2_명제.html` 주제1~4). `examprep_reference_집합과명제_함수_2026.txt`
에서 명제·조건·필요충분조건·귀류법 관련 실제 기출 표현을 그라운딩으로 사용(집합/함수 문제와 섞여 있어 명제
관련 부분만 선별).

**주의(중요)**: `공수2_명제.html`은 `공수2_집합과명제.html`(집합+명제 통합 원본)에서 명제 파트(원본의
주제2~5)만 복사해 만든 파일입니다. 원본에는 지도1~6(부분집합개수/필요충분연쇄/명제부정/반례찾기/귀류법/하브루타)이
있지만, **이 지도 카드들은 명제.html로 복사되지 않았습니다** — 아래 A섹션의 "연결 카드"가 가리키는 지도2~5는
현재 `공수2_집합과명제.html`(원본, 절대 수정 금지)에만 존재합니다. 역참조 시 반드시 "원본 파일의 지도N"이라고
명시할 것 — 명제.html만 보는 학생은 못 찾습니다.

## A. 검증된 서랍 — 원본 파일(공수2_집합과명제.html)의 지도카드와 연결됨 (역참조 필수, 단 명제.html엔 지도 자체가 없음)

### A1. 필요·충분조건 판별 (기본형)
- **메커니즘**: p, q가 이미 정해진 조건일 때 P, Q의 포함관계(P⊂Q / Q⊂P / P=Q)를 직접 비교해 "p는 q이기
  위한 무슨 조건인가"를 판별.
- **연결 카드**: 명제.html 주제3(필요·충분조건) 개념+기본3
- **난이도 신호**: 체이닝 1단계 / 케이스분류 0개 / 정수론 없음 / 동시조건 0개
- **현재 사용처**: 명제.html 기본3

### A2. 필요·충분조건 연쇄 (포함관계 사슬)
- **메커니즘**: 세 조건의 진리집합 포함관계가 R⊂P⊂Q처럼 사슬로 주어지고, 두 조건 사이의 관계(예: r은
  q이기 위한 무슨 조건인가)를 화살표를 이어 붙여 판정.
- **연결 카드**: 원본 `공수2_집합과명제.html`의 **지도2/6**(② 필요·충분조건 — 진리집합 포함관계 연쇄).
  명제.html엔 아직 이 지도 카드가 없음 — 개념 자체는 주제3과 동일 원리.
- **난이도 신호**: 체이닝 2단계(R⊂P, P⊂Q를 이어 R⊂Q 도출) / 케이스분류 0개 / 정수론 없음 / 동시조건 2개
- **현재 사용처**: (명제.html엔 미배치 — 원본 지도2에만 존재)

### A3. 명제의 부정 (드모르간)
- **메커니즘**: "그리고"/"또는"이 들어간 명제의 부정을 드모르간의 법칙으로 구함.
- **연결 카드**: 원본 `공수2_집합과명제.html`의 **지도3/6**(③ 명제의 부정). 명제.html엔 미배치.
- **난이도 신호**: 체이닝 1단계 / 케이스분류 0개 / 정수론 없음 / 동시조건 0개
- **현재 사용처**: (명제.html엔 미배치 — 원본 지도3에만 존재)

### A4. 반례 찾기 (단일)
- **메커니즘**: "모든 x에 대하여" 명제는 반례 하나만 찾아도 거짓임을 보일 수 있다는 원리로 반례 1개를 탐색.
- **연결 카드**: 원본 `공수2_집합과명제.html`의 **지도4/6**(④ 반례 찾기). 명제.html엔 미배치이지만, 아래
  B2(반례 개수 세기)의 개념카드가 이 원리를 다시 짚어줌.
- **난이도 신호**: 체이닝 1~2단계 / 케이스분류 0개(반례 1개만 찾으면 종료) / 정수론 조건부(배수 관련 소재
  많음) / 동시조건 0개
- **현재 사용처**: (명제.html엔 미배치 — 원본 지도4에만 존재. B2가 이 서랍을 "개수 세기"로 확장한 버전)

### A5. 귀류법
- **메커니즘**: 결론을 부정하고 시작해 원래 조건과 충돌하는 모순을 찾아 원 결론이 참임을 증명. 대우 증명과
  달리 "반대 가정 → 결론까지 순탄하게 도착"이 아니라 "반대 가정 → 가다가 모순과 충돌".
- **연결 카드**: 원본 `공수2_집합과명제.html`의 **지도5/6**(⑤ 귀류법) + 지도6/6(하브루타 — 대우 증명과
  귀류법의 차이). 명제.html 주제4(명제의 증명) 개념카드가 대우 증명과 귀류법 둘 다 소개하지만, 귀류법
  단독 문제(예: √2가 무리수임을 증명)는 명제.html 기본4에 아직 없음(기본4는 대우 증명만 다룸).
- **난이도 신호**: 체이닝 3단계(반대 가정→계산 진행→모순 발견) / 케이스분류 0개 / 정수론 있음(기약분수 등)
  / 동시조건 0개
- **현재 사용처**: (명제.html엔 미배치 — 원본 지도5·지도6에만 존재)

## B. 신규 서랍 — 참고자료에서 새로 발견, 이번에 명제.html에 카드 추가 완료 (2026-07-25)

### B1. 필요·충분조건 역산형
- **메커니즘**: A1(기본형)과 정반대 방향. p, q의 진리집합 중 하나(또는 둘 다)에 미지수 a가 들어있고,
  "p가 q이기 위한 충분조건(또는 필요조건)이 되도록 하는 상수 a의 범위/최댓값·최솟값을 구하라"처럼
  **포함조건(P⊂Q)에서 거꾸로 미지수를 역산**해야 함. A1은 조건을 보고 관계를 "판별"하는 데 그치지만,
  B1은 관계(충분/필요)가 이미 주어지고 그 관계가 성립하도록 미지수 쪽을 "설계"해야 함 — 방향이 반대라는 점이
  A1과의 핵심 대비쌍 포인트.
- **연결 카드**: 명제.html 주제3(필요·충분조건) — 신규 카드의 "구조 신호" 박스에서 직접 역참조함.
- **난이도 신호**: 체이닝 2단계(인수분해로 진리집합 구하기 → 구간 양 끝 부등식 비교) / 케이스분류 0개(이번
  설계는 인수분해 시 판별식이 항상 완전제곱이라 공집합 케이스 없음 — 원 참고자료 문제 중엔 공집합 가능성을
  따로 검토해야 하는 경우도 있어 향후 심화 시 케이스분류 1개 추가 여지 있음) / 정수론 없음(정수 조건 있는
  최댓값/최솟값 합산은 있음) / 동시조건 2개(양쪽 끝 부등식 동시 만족)
- **그라운딩**: `examprep_reference_집합과명제_함수_2026.txt` 692행(필요·충분조건 최댓값), 1061행(충분조건
  이고 필요조건 아닐 때 상수), 1401행(포함조건 최댓값), 1501행(필요조건 범위), 2837행(충분조건 정수
  최댓값+최솟값 합), 4695행(필요조건 되도록 하는 상수 값) — 동일 구조가 최소 6회 반복 확인됨.
- **현재 사용처**: 명제.html "필요·충분조건 역산 — 신규문제"(신규 1)

### B2. 반례 개수 세기
- **메커니즘**: A4(반례 찾기, 단일)의 확장. "반례가 몇 가지인지 세어라"는 요구 — 반례를 하나씩 나열하는
  게 아니라 "(p를 만족하는 개수) − (p와 q를 모두 만족하는 개수)"라는 차집합 계산으로 접근. 정수론적
  케이스분류(배수·최소공배수)가 필요.
- **연결 카드**: 명제.html 주제4(명제의 증명) 및 원본 지도4(반례 찾기) — 신규 카드의 "구조 신호" 박스에서
  "반례 하나만 찾는 기존 문제와 다르다"는 점을 명시적으로 대비시킴.
- **난이도 신호**: 체이닝 2단계(배수 개수 세기 → 공배수 개수 빼기) / 케이스분류 0개(단, 배수·공배수 계산
  자체가 정수론적 사고 요구) / **정수론 있음(최소공배수)** / 동시조건 1개
- **그라운딩**: `examprep_reference_집합과명제_함수_2026.txt` 414~420행("100보다 작은 자연수... 반례는
  모두 몇 가지인가"), 1560~1573행(같은 유형이 풀이와 함께 반복 등장) — 2회 확인.
- **현재 사용처**: 명제.html "반례 개수 세기 — 신규문제"(신규 2)

### B3. 대우를 새 정보로 쓰는 연쇄 추론
- **메커니즘**: 명제 여러 개(p→q, q→r, r→s 등)가 동시에 참이라고 주어지고, 삼단논법(화살표 잇기)과
  대우(반대+부정)를 함께 사용해 <보기> 속 여러 명제의 참·거짓을 판정하는 결합형. 흔한 함정은 "역"(q→p,
  s→r 등 방향이 반대인 것)을 대우와 혼동해 참으로 잘못 판단하는 것 — 대우는 항상 원명제와 동치이지만
  역은 별도 증명 없이는 참을 보장할 수 없다는 차이를 정확히 아는지 시험함.
- **연결 카드**: 명제.html 주제2(역·이·대우) + 주제3(필요·충분조건, P⊂Q⊂R⊂S 포함관계 사슬) — 신규
  카드의 "구조 신호" 박스에서 두 주제를 동시에 참고하라고 명시.
- **난이도 신호**: 체이닝 3단계(전이 관계 확인 → 대우 도출 → 역방향 오답 소거) / 케이스분류 0개(보기 항목
  4개를 각각 참/거짓 판정하는 방식) / 정수론 없음 / 동시조건 3개(세 명제 p→q, q→r, r→s가 동시에 참)
- **그라운딩**: `examprep_reference_집합과명제_함수_2026.txt` 258~264행("세 명제가 모두 참일 때 반드시
  참이라고 할 수 없는 것은?" 5지선다), 1168~1178행("두 명제가 참일 때 참인 명제만을 <보기>에서 고른
  것은?" ㄱㄴㄷㄹ 보기형) — 2회 확인, 형식은 5지선다/보기형 둘 다 등장.
- **현재 사용처**: 명제.html "대우 연쇄추론 — 신규문제"(신규 3, ㄱㄴㄷㄹ 보기형 채택)

## C. 대비쌍 관계

### A1 ↔ B1 (필요·충분조건 판별 vs 역산)
겉보기엔 둘 다 "p는 q이기 위한 무슨 조건"을 다루는 필요·충분조건 문제라 헷갈리기 쉽지만, **방향이
정반대**: A1은 조건이 확정된 상태에서 관계를 읽어내는 문제(진리집합을 구해서 포함관계를 판별), B1은
관계(충분/필요)가 이미 주어지고 그 관계를 만족시키는 미지수를 거꾸로 설계하는 문제. 세트 구성 시 두 문제를
연달아 배치하지 말고, 사이에 다른 유형(B2, B3 등)을 끼워 인터리빙할 것.

### A4 ↔ B2 (반례 찾기 vs 반례 개수 세기)
같은 소재(배수 조건, "모든 자연수 n에 대하여" 형식)를 쓰지만 요구하는 답의 형태가 다름: A4는 반례 "하나"만
제시하면 끝나는 문제, B2는 반례의 "총 개수"를 정수론적으로 세야 하는 문제. 학생이 A4 방식(반례 하나 찾고
끝)으로 B2에 접근하면 미완성 답(예: "n=4가 반례입니다"만 쓰고 끝)을 낼 위험이 큼 — 두 유형을 명시적으로
구분해서 인식시켜야 함.

## D. 향후 보완 필요

- 원본 `공수2_집합과명제.html`의 지도2~6이 아직 `공수2_명제.html`로 이식되지 않은 상태. A2~A5의
  "연결 카드"가 가리키는 실제 카드가 명제.html엔 없으므로, 학생이 명제.html만 보고 공부할 경우 역참조가
  끊김. 추후 지도카드 이식 작업이 필요함(이번 작업 범위 밖).
- B1의 "케이스분류 0개"는 이번에 설계한 문제(인수분해가 항상 완전제곱)에 한정된 값. 참고자료 원문 중에는
  진리집합이 공집합이 될 수 있는 조건(판별식 음수 등)을 포함한 문제도 있어 보여, 심화 버전에서는 케이스
  분류 1개(공집합 여부 확인)를 추가할 여지가 있음.
