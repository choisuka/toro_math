# drawer-trainer — 서랍 인식·조합 훈련 프로토타입

**시작일**: 2026-07-19
**상태**: 계획만 있음, 코드 아직 없음

## 왜 만드는가 (구현 전에 먼저 적어둠)

시중 문제집은 유형(서랍)별로 예제를 묶어놓지만, 예제마다 소재가 달라서 학생이 "같은 유형인지" 자체를 못 알아본다는 게 원래 문제의식이었다([[project-toro-math-release]] 관련 논의). 이 도구는 그 인식 능력만 따로 떼어서 훈련·채점하는 게 목적이다 — **계산해서 정답 맞히는 건 이 도구의 범위가 아니다.** 계산 풀이·채점·오답노트는 학원에서 사람이 한다.

`examprep-checker`(같은 toro_math 안의 다른 프로젝트)와는 다르다 — examprep-checker는 토로매쓰가 이미 만든 문제 파일을 검사하는 도구고, 이건 **시중 문제집 사진을 입력받아 새로 서랍/조합문제를 만들고 학생 설명을 채점하는** 별개의 앱이다.

## 확정된 전체 흐름 (2026-07-19)

1. **사진 입력** — 시중 문제집 한 단원을 실제 사진으로 입력 (카메라/업로드)
2. **서랍 추출** — 사진 속 문제들을 분석해서 그 단원에 나오는 모든 서랍(유형)을 추출
3. **서랍 암기 테스트** — 추출된 서랍 자체를 학생이 알고 있는지 먼저 테스트 (조합 문제보다 먼저)
4. **조합 문제 생성** — 서랍 2개 이상을 조합한 문제의 **지문만** 생성 (계산 문제가 아님)
5. **학생 설명 입력** — 학생이 "이 문제는 서랍 A, B가 이렇게 조합됐다"를 주관식으로 씀
6. **실제 채점** — 학생의 주관식 설명을 시스템이 실제로 채점 (정답 보여주고 자가채점 아님)
7. **(범위 밖)** 실제 계산 풀이·채점·오답노트는 학원에서 사람이 진행

## 기술적으로 중요한 점

- 2번(사진→서랍 추출)과 6번(주관식 채점)은 **실제 AI 모델 호출이 필요**하다. 이건 Claude Code 세션 안에서 무료로 쓰던 서브에이전트 방식과 다르다 — 실제 API 키를 발급받아 호출당 비용이 발생하는 구조다([[feedback... API 비용 논의]] 참고, 2026-07 초 대화에서 이미 짚었음).
- 그래서 처음부터 완전한 앱(로그인, 다수 학생 관리, DB)을 만들지 않고, **파이프라인 자체가 실제로 작동하는지 확인하는 작은 프로토타입**부터 만들기로 함 (2026-07-19 결정).
